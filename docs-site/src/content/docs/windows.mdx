**SWSD for AI apps** is the Windows companion for the `swsd` plugin. It installs the local tools, verifies your JSON Web Token, and saves the profile those tools use.

## Install and open

1. Install the Windows `swsd` plugin.
2. Start a new local chat and ask to set up SWSD on this computer.
3. In **Set up**, select **Install tools**. This PC needs Node.js 24.15+ or Node.js 26+, with npm. Node 25 is not supported. When Node.js is missing or unsupported, setup can install the current supported LTS through winget after you confirm. Reopen **SWSD Setup** when that installation finishes.
4. Choose **United States** (`https://api.samanage.com`) or **Europe** (`https://apieu.samanage.com`), paste your JSON Web Token, and select **Test**. The field stays masked. A successful test stores the token in Windows Credential Manager and shows the connected account.
5. Choose a profile. The choice is saved immediately. Quit and reopen the AI app, then start a new chat so the server loads that tool set.
6. Open the app again from **SWSD Setup** on the Start menu.

Changing the region clears the verified state until you select **Test** again. **?** beside **JSON Web Token**, and **Where do I find my token?**, show the SWSD User detail page. Generate a JSON Web Token only when none is shown.

Settings, custom profiles, and the installed tools live under `%LOCALAPPDATA%\swsd-mcp`. The token stays in Windows Credential Manager. See [Security](/security/#zero-credentials-at-rest).

## Connection and status

After tools are installed and **Test** succeeds, Home replaces **Set up** with **Overview**:

| Status | What it reports |
|---|---|
| Node.js | Installed version, and whether it is a supported release |
| SWSD tools | Installed `swsd-mcp` version |
| JSON Web Token | Masked value and **Verified** after a successful test |
| Region | United States or Europe |
| Profile | Active profile and its tool count |
| Updates | **Up to date**, or a newer published version |

**Repair** reinstalls the pinned tools. **Remove saved JSON Web Token** deletes the credential stored on this PC. Quit the AI app afterwards so a running server stops using its in-memory copy. Removing the saved credential leaves the token active in SWSD until an administrator revokes it there.

## Tool guide

**Tools** lists every tool in the catalog, with the count enabled by the current profile. **Ctrl+F** focuses the search box. Search matches the friendly name, the tool id, and the description. Area chips limit the list to the tools that profile includes, such as Incidents or Knowledge.

Each row has a **Read**, **Edit**, or **Delete** badge. Read looks up records, Edit creates or changes them, and Delete is always previewed. Tools outside the profile stay under **Not in** that profile until you search. A search result for a tool outside the profile shows a lock with a profile that includes it, and the detail can switch to that profile.

Selecting a tool shows the profiles that include it and an example prompt. **Copy prompt** copies that example. Delete tools include the notice that they are destructive, available in Operations, and preview the record before a confirmed delete.

## Custom profiles

Open **Custom profiles** on Tools to build a named set:

1. Enter a name and an optional description.
2. Check the tools your AI apps may use.
3. Select **Save profile**. The profile becomes the active selection and appears in the Home and Tools pickers.

**Rename** saves the profile under the new name. **Delete** removes it. Deleting the active custom profile returns the selection to **Agent**. **New** clears the form.

**Export JSON** writes the profile to a file you choose. **Import JSON** reads a file into the builder. Import does not switch the active profile until you select **Save profile**. The file is the same version-1 profile documented in [Custom profiles](/configuration/#custom-profiles): `name`, `version`, `tools`, and an optional `description`. Extra fields are rejected with **Profile JSON: Only name, version, tools, and optional description are allowed.** Unknown tool names are skipped and listed. A name that matches Triage, Agent, Knowledge, Operations, or Full is rejected.

Other MCP clients still select the file with `SWSD_PROFILE=custom` and `SWSD_PROFILE_FILE`.

| Profile | Tools | Use |
|---|---:|---|
| Triage | 21 | Incident review, catalog context, task and problem visibility, and comments |
| Agent | 51 | Everyday ticket handling, tasks, problems, time entries, attachments, and knowledge search |
| Knowledge | 17 | Knowledge search, article creation and updates, and incident context |
| Operations | 145 | Every tool. SWSD account permissions still apply |
| Custom | Your list | The tools checked in the builder |

Older settings saved as Full open as Operations.

## Updates, diagnostics, and release notes

**Check now** looks up the newest published `swsd-mcp` release. When one is newer, the row reads that a version is available and the button becomes **Update**. Update installs that release only after the package checks out, and keeps the current tools if the install does not finish.

**What's new** opens the bundled release notes inside the app. Notes that are not in a published release are labeled **Upcoming**. Opening the page does not use the network.

**Copy report** copies a plain-text diagnostics report: app and package versions, Windows and PowerShell versions, Node.js, whether tools are installed, the profile, the region URL, credential presence, display scale, and the last 20 log lines. The report records whether a credential is present. It does not include the token. Log lines are redacted.

**Report a bug** and **Request a feature** open the GitHub form with the app version, server version, Windows version, and profile filled in.
