The Windows `swsd` plugin includes a settings window for installing swsd-mcp on this PC and for changing that setup later. The window is titled **SWSD for AI apps**. It installs the local tools, saves your JSON Web Token in Windows Credential Manager, and chooses the profile those tools use.

## Set up this PC

1. Install the Windows `swsd` plugin.
2. Start a new local chat and ask to set up SWSD on this computer.
3. On **Set up**, select **Install tools**. Windows setup accepts Node.js 24.15 or newer within version 24, or Node.js 26 or newer, with npm. The window rejects other versions, and its message says Node 25 is not supported. When Node.js is missing, setup can install the current Node.js LTS through winget after you confirm. Windows may ask for administrator approval. Reopen the window when that installation finishes.
4. Choose **United States** (`https://api.samanage.com`) or **Europe** (`https://apieu.samanage.com`), paste your JSON Web Token, and select **Test**. The field stays masked.
5. Choose a profile. The choice is saved immediately. Quit and reopen the AI app, then start a new chat so the server loads that tool set.
6. Open the window again from **SWSD Setup** on the Start menu.

**?** beside **JSON Web Token**, and **Where do I find my token?**, open **Get your JSON Web Token in SWSD**. That help shows the User detail page. Use **Actions → Generate JSON Web Token** only when no token is shown.

Settings, custom profiles, and the installed tools live under `%LOCALAPPDATA%\swsd-mcp`. The token stays in Windows Credential Manager. See [Security](/security/#zero-credentials-at-rest).

## Connection and status

After the tools are installed, **Home** is titled **Overview**. The status row reports:

| Status | What it reports |
|---|---|
| Node.js | Installed version, and whether Windows setup accepts it |
| SWSD tools | Installed `swsd-mcp` version |
| JSON Web Token | Masked value, and **Verified** after **Test** |
| Region | **United States** or **Europe** |
| Profile | Active profile and its tool count |
| Updates | **Up to date**, or that a newer published release is available |

Changing the region clears the verified state until you select **Test** again. **Repair** reinstalls the tools. **Remove saved JSON Web Token** deletes the credential stored on this PC. Quit the AI app afterwards so a running server stops using its in-memory copy. Removing the saved credential leaves the token active in SWSD until it is revoked there.

## Tool guide

**Tools** lists every tool in the catalog. The heading shows how many of the 145 tools the current profile enables. **Ctrl+F** focuses **Search tools**. Search matches the friendly name, the tool id, and the description. An empty search says **No tools found. Try a friendly name, tool ID, or area.**

Area chips limit the list to tools that profile includes, such as Incidents or Knowledge. Each row has a **Read**, **Edit**, or **Delete** badge. Read looks up records, Edit creates or changes them, and Delete is always previewed. A delete tool also says it is destructive, available in Operations, and previews the record before a confirmed delete.

Tools outside the profile stay under **Not in** that profile until you search. A search result outside the profile shows a lock with a profile that includes it, and the detail can switch to that profile. Selecting a tool shows the profiles that include it and an example prompt. **Copy prompt** copies that example.

## Custom profiles

Open **Custom profiles** on Tools:

1. Enter a name and an optional description.
2. Check the tools your AI apps may use.
3. Select **Save profile**. The profile becomes the active selection and appears in the Home and Tools pickers.

**Rename** saves the profile under the new name. **Delete** removes it. Deleting the active custom profile returns the selection to **Agent**. **New** clears the form.

**Export JSON** writes the profile to a file you choose. **Import JSON** reads a file into the builder. Import does not switch the active profile until you select **Save profile**. The file is the same version-1 profile documented in [Custom profiles](/configuration/#custom-profiles): `name`, `version`, `tools`, and an optional `description`. Extra fields are rejected with **Profile JSON: Only name, version, tools, and optional description are allowed.** Unknown tool names are skipped and listed. A name that matches Triage, Agent, Knowledge, Operations, or Full is rejected.

## Updates, diagnostics, and release notes

**Check now** looks up the newest published `swsd-mcp` release. When one is newer than the installed tools, the row says a version is available and the button becomes **Update**. Update installs that release only after the package checks out, and keeps the current tools if the install does not finish.

**What's new** opens the bundled release notes inside the window. Notes that are not in a published release are labeled **Upcoming**. Opening the page does not use the network.

![What's new page. Upcoming shows the Node.js note, followed by the 3.3.0 notes. The account line reads Alex Rivera, Acme IT.](/windows/whats-new.png)

*Demo What's new page. Upcoming shows the Node.js note, then the 3.3.0 notes. The account line reads Alex Rivera · Acme IT.*

**Copy report** copies a plain-text diagnostics report: app and package versions, Windows and PowerShell versions, Node.js, whether tools are installed, the profile, the region URL, credential presence, display scale, and the last 20 log lines. The report records whether a credential is present. It does not include the token. Log lines are redacted.
